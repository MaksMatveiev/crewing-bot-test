# Крюинг-бот записи на интервью

Веб-чат крюингового агентства: моряк выбирает вакансию, проходит анкету и
скрининг, бронирует слот на интервью. Всё пишется в Postgres. Вторая
вкладка — рабочее место рекрутера под паролем.

## Паттерны внутри

| Паттерн | Где | Что делает |
|---|---|---|
| RAG | `knowledge.md` + `brain.answer` | отвечает по фактам агентства и вакансии |
| Router | `brain.looks_like_question` | отличает ответ по анкете от встречного вопроса — проверкой текста, без обращения к модели |
| Structured Output | `brain.extract` | свободный текст → поля анкеты |
| Tool Calling | `db.book_slot`, `db.create_application` | реальная бронь и запись в базу |
| Memory | `funnel.State` в `gr.State` | воронка помнит, на чём остановились |
| Judge | `brain.verdict` | оценка кандидата для менеджера |

## Запуск

```bash
uv pip install -r requirements.txt
# .env: GOOGLE_API_KEY, DATABASE_URL, RECRUITER_PASSWORD
python crewing_bot/app.py
```

Откроется на http://localhost:7861

## Тесты

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe -m pytest crewing_bot/tests -v
```

Тесты воронки, склейки и модели идут без сети и без базы — они выполняются
всегда.

Тесты базы делают `TRUNCATE` таблиц, поэтому идут **только** в базу из
`TEST_DATABASE_URL`. Отката на `DATABASE_URL` нет специально: иначе команда
выше вычистила бы рабочую базу вместе с настоящими заявками кандидатов. Если
`TEST_DATABASE_URL` не задана, эти тесты пропускаются с объяснением, а
остальные проходят.

Проверяется не имя переменной, а сама строка подключения: если
`TEST_DATABASE_URL` совпадает с `DATABASE_URL` (краевые пробелы не в счёт),
тесты базы тоже пропускаются — это одна и та же база, и прогон стёр бы
рабочие данные.

Чтобы прогнать и их, заведи **отдельный** проект Supabase и пропиши его строку
подключения в `TEST_DATABASE_URL` (в `.env` её класть не нужно — достаточно
задать в команде запуска):

```bash
PYTHONIOENCODING=utf-8 TEST_DATABASE_URL="postgresql://..." \
  .venv/Scripts/python.exe -m pytest crewing_bot/tests -v
```

На Windows добавляй `PYTHONIOENCODING=utf-8` — иначе консоль падает на
кириллице в выводе.

## База данных

Четыре таблицы, создаются сами при первом запуске: `vacancies`, `slots`,
`candidates`, `applications`.

Схема готовится **один раз за процесс**, а не на каждое сообщение: создание
таблиц, миграция и индексы на горячем пути — лишняя нагрузка и лишний повод
упасть. Если подготовка не удалась, кандидат и рекрутер видят понятный текст,
а не ошибку интерфейса; следующий вызов попробует снова.

Перед постановкой уникального индекса по `lower(contact)` идёт миграция:
на базе, пожившей со старым багом, строки, отличающиеся только регистром
контакта, сливаются в самую раннюю (`min(id)`), её заявки переносятся на неё
же, лишние активные заявки получают статус `duplicate`. Ни одна заявка не
удаляется — удаляются только опустевшие строки-дубликаты кандидата.

Две гарантии зашиты в базу, а не в код:
- слот нельзя забронировать дважды — условие `status='open'` прямо в `UPDATE`;
- у моряка не может быть двух назначенных интервью — частичный уникальный
  индекс по `candidate_id` при `status='new'`;
- один моряк — одна строка независимо от регистра контакта: `db` приводит
  контакт к нижнему регистру при записи и поиске, а уникальный индекс по
  `lower(contact)` страхует от строк, заведённых мимо `upsert_candidate`.

## Что видит кандидат

Сразу — вакансии карточками: снимок судна, должность, тип флота, ставка,
срок контракта и кнопка «Записаться на интервью». Разговора на входе нет:
человек пришёл смотреть места, а не отвечать на вопросы.

Должность не набирают руками — её выбирают из списка, где рядом с каждой
стоит число открытых мест. Значков в карточках нет: должность ищут
глазами, и картинки рядом с текстом мешают.

Помощник появляется сбоку только после нажатия «Записаться» и ведёт ту же
воронку: анкета, скрининг, выбор времени. Если ни один день в календаре
не открыт, бот говорит об этом сразу и не ведёт человека через анкету
ради отказа в конце.

## Канал с вакансиями в Telegram

Раз в сутки бот сам выкладывает в канал все открытые вакансии. Час
задаётся переменной `PUBLISH_HOUR` (по умолчанию 8, время UTC).

Объявление выглядит так, как принято у моряков: должность со ставкой
сверху, ниже данные судна — дата посадки, год постройки, тип и дедвейт,
срок контракта, двигатель, — и контакты агентства внизу. Пустые поля
пропускаются: строка «Built: —» не добавляет ничего. Снимок судна идёт
вместе с текстом.

Уже опубликованная вакансия правится, а не публикуется заново, поэтому
в канале не копятся повторы. Закрытие вакансии тоже правит пост, помечая
его словом «закрыта»: удалять нельзя — ссылку могли переслать.

Отметка о сделанном лежит в базе, а не в памяти: бесплатный хостинг
засыпает и просыпается, и без отметки канал получал бы один и тот же
список по нескольку раз за день. Обещание такое: выложить сегодня, при
первой возможности после назначенного часа, и ровно один раз. На
бесплатном тарифе Render спящий сервис никто не будит, поэтому выкладка
случится, когда на сайт зайдёт первый посетитель после восьми утра.

Что нужно настроить один раз:

1. Создать канал и добавить бота его администратором с правом
   публиковать сообщения.
2. `TELEGRAM_CHANNEL` — `@имя_канала` или числовой `-100…`.
3. `SITE_URL` — адрес сайта, он уходит ссылкой в объявление.
4. `AGENCY_EMAIL` и `AGENCY_PHONES` — контакты в подписи. Телефоны
   перечисляются через точку с запятой.

Без `TELEGRAM_CHANNEL` публикация просто выключена.

## Вкладка рекрутера

Вход по паролю из `RECRUITER_PASSWORD`. Поля появляются только после
входа, но прятать их — лишь внешний вид: каждый обработчик проверяет
пароль сам, иначе защиту обошли бы запросом мимо интерфейса.

Две вкладки и ничего лишнего:

- **Вакансии** — те же карточки, что видит кандидат, плюс закрытые и
  фильтр «все / открытые / закрытые». Кнопка «+ Новая вакансия» открывает
  пустую форму, «Изменить» на карточке — форму с этой вакансией.
  **Удаления нет нигде — ни в интерфейсе, ни в `db`.** На вакансию
  ссылаются заявки кандидатов: стереть её значит потерять историю.
  Вместо удаления вакансию закрывают.
- **Календарь** — небольшой, рядом с вакансиями. Нажатие на день
  открывает его часы: зелёный час — приём открыт, повторное нажатие
  снимает его. Кнопки «Открыть весь день» и «Снять день» делают то же
  разом. Занятый час не снимается никогда: за ним стоит человек,
  которому уже назвали время. Ровно эти даты видит кандидат. Под
  календарём — список записавшихся.

Время слотов хранится и показывается в **UTC** — и рекрутеру, и кандидату.
Часовой пояс сессии задаётся явно при подключении (`options=-c timezone=UTC`):
наивное время читается обратно в поясе сессии, и без этого подпись «UTC» была
бы верна только на базе, у которой пояс и так UTC.

## Скорость и квота модели

Бесплатный тариф Google даёт **20 запросов в сутки на каждую модель**.
Бот тратит один запрос на сообщение кандидата — разбор ответа в поля
анкеты. Определение «ответ это или встречный вопрос» модели не требует:
знак вопроса и вопросительное слово видны проверкой текста.

Имя модели берётся из переменной `GEMINI_MODEL`. По умолчанию
`gemini-flash-lite-latest` — у неё своя квота, отдельная от остальных.
Когда суточный лимит основной модели свободен, `gemini-3.6-flash`
отвечает примерно втрое быстрее: смена значения переменной в дашборде
Render не требует ни правки кода, ни нового деплоя.

## Деплой

Сервис `crewing-ai` в `render.yaml`. В дашборде Render задать
`GOOGLE_API_KEY`, `DATABASE_URL`, `RECRUITER_PASSWORD`.

Прямое подключение к Supabase (вида `db.<ref>.supabase.co`) не работает без IPv6.
Используй **Session pooler** (вида `postgresql://postgres.<ref>:ПАРОЛЬ@aws-0-<регион>.pooler.supabase.com:5432/postgres`)
из окна Connection string в Supabase. Это касается как запуска локально, так и деплоя на Render.

## Карточка заявки в Telegram

После брони бот показывает кандидату ссылку. Кандидат жмёт её, нажимает
«Начать» — и получает карточку: вакансия, время интервью, его данные.

Фича необязательная: без переменных ниже бот работает как обычно.

### Настройка

1. Завести бота у **@BotFather**: команда `/newbot`, получить токен и имя.
2. Придумать случайную строку для `TELEGRAM_WEBHOOK_SECRET`.
3. Задать три переменные — в `.env` локально и в дашборде Render.
4. После деплоя один раз зарегистрировать адрес вебхука в Telegram:

```bash
curl -X POST "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
  -d "url=https://<адрес-сервиса>/telegram/webhook" \
  -d "secret_token=<СЕКРЕТ>"
```

Проверить, что Telegram принял адрес:

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"
```

### Что важно знать

- **Telegram не может написать первым.** Пока кандидат не нажал Start,
  отправить ему нечего — поэтому и нужна ссылка.
- **Ссылка привязывается к первому, кто её открыл.** Переслал другу —
  друг получит вежливый отказ, а не чужие данные.
- **Вердикт модели в карточку не попадает.** Это заметка для рекрутера.
- **Первая карточка может прийти с задержкой до минуты:** на бесплатном
  плане сервис засыпает, и запрос Telegram сначала его будит.
