# Карточка заявки в Telegram — дизайн

Дата: 2026-09-10
Статус: утверждён к реализации
Проект: crewing-bot (Gradio + Postgres/Supabase, Render)

## Что строим

После того как моряк забронировал слот на интервью, бот показывает ему
ссылку на Telegram. Кандидат жмёт её, нажимает Start и получает карточку
своей заявки: вакансия, дата и время интервью, его данные, контакт
менеджера.

Дальше бот в Telegram молчит. Ни напоминаний, ни отмены, ни переноса —
это отдельные задачи, если понадобятся.

## Главное ограничение

**Telegram-бот не может написать человеку первым.** Пока кандидат не
нажал Start, у нас нет его `chat_id`, и отправить ему нечего. Отправки
по `@username` в API не существует.

Отсюда весь дизайн: мы не «отправляем кандидату», мы даём ему ссылку,
по которой он сам открывает разговор, а мы отвечаем.

## Решения и их основания

| Решение | Почему так |
|---|---|
| Вебхук, а не long polling | На бесплатном Render сервис засыпает. Запрос Telegram его будит; при polling нажатие Start потерялось бы навсегда, потому что будить некому |
| Вебхук в том же сервисе, а не отдельным | Один деплой, одна точка отказа. Ради одного эндпоинта второй сервис не нужен |
| Код привязывается к первому `chat_id` | Ссылка может уйти не туда — пересылка, скриншот. Без привязки любой открывший увидел бы ФИО, контакт и ответы чужого человека |
| Вердикт модели в карточку не попадает | Это внутренняя заметка для рекрутера. Кандидату его оценку за глаза не показывают |
| Без токена бота фича просто выключена | Бот обязан работать и без Telegram: не задана переменная — ссылка не показывается, всё остальное как прежде |

## Данные

Две колонки в `applications`:

| Поле | Тип | Смысл |
|---|---|---|
| `telegram_token` | TEXT UNIQUE | Код для ссылки. Генерируется внутри сохранения заявки, одной операцией с ней |
| `telegram_chat_id` | BIGINT | Заполняется, когда кандидат нажал Start |

Поля на заявке, а не на кандидате: карточка описывает конкретное
интервью. У моряка со временем может быть их несколько, и ссылка должна
вести на нужное.

Код — случайный, не угадываемый перебором: `secrets.token_urlsafe(16)`.
Это не украшение: адрес вебхука публичный, и короткий предсказуемый код
означал бы, что чужие заявки достаются подбором.

Миграция: колонки добавляются через `ALTER TABLE ... ADD COLUMN IF NOT
EXISTS` в существующем механизме `init_schema`, рядом с миграцией
контактов. Существующие заявки останутся без кода — это нормально, они
созданы до появления фичи.

## Поток

1. Слот забронирован. Код генерируется **внутри сохранения заявки**,
   одной операцией с ней: если заявка есть — код у неё есть всегда.
2. Вердикт модели дописывается отдельно, как и раньше.
3. Бот в веб-чате показывает подтверждение и ссылку
   `https://t.me/<имя_бота>?start=<код>`.
4. Кандидат открывает ссылку и нажимает Start. Telegram шлёт на
   `/telegram/webhook` сообщение с текстом `/start <код>`.
5. Сервер проверяет секретный заголовок, находит заявку по коду.
6. Если `telegram_chat_id` пуст — записывает `chat_id` отправителя.
   Если заполнен и совпадает — просто отправляет карточку снова.
   Если заполнен и не совпадает — вежливый отказ, карточка не уходит.
7. Карточка отправляется в Telegram.

## Карточка

Содержит: должность и тип судна, дату и время интервью с пометкой UTC,
имя кандидата, его контакт, дату готовности к контракту, строку о том,
как связаться с менеджером.

Не содержит: вердикт модели, ответы скрининга, внутренние заметки.

## Устройство

| Файл | Ответственность |
|---|---|
| `crewing_bot/telegram.py` | Разбор входящего сообщения (чистая функция), сборка текста карточки, отправка в Telegram |
| `crewing_bot/db.py` | Генерация кода при создании заявки, поиск заявки по коду, привязка `chat_id` |
| `crewing_bot/app.py` | Показ ссылки после брони; веб-приложение с двумя адресами |

Граница: разбор апдейта и сборка карточки не ходят в сеть и не знают про
базу — им передают готовые данные. Отправка в Telegram — отдельная
функция. Так обработчик проверяется тестами целиком, без сети.

**Точка входа меняется.** Сейчас Gradio поднимает сервер сам. Станет:
веб-приложение с маршрутом `/telegram/webhook`, в которое Gradio
смонтирован на `/`. Порт и переменная `PORT` — как прежде.

## Отказы

| Ситуация | Поведение |
|---|---|
| `TELEGRAM_BOT_TOKEN` не задан | Ссылка не показывается, вебхук отвечает отказом. Веб-чат работает полностью |
| Нет или неверен секретный заголовок | 403, ничего не делается. Без этой проверки любой мог бы слать поддельные апдейты на публичный адрес |
| Код не найден | Ответ «ссылка не найдена или устарела». Без подробностей: подсказки помогли бы перебору |
| Код занят другим `chat_id` | Вежливый отказ, карточка не уходит |
| Telegram не принял сообщение | Заявка и бронь уже сохранены, ничего не теряется. Ошибка в лог, вебхук отвечает 200 |
| Апдейт не про `/start` | Игнорируется, 200 |

На любой корректно подписанный апдейт отвечаем 200, даже когда по сути
отказали: иначе Telegram будет повторять доставку часами.

Холодный старт: первые попытки доставки упрутся в спящий сервис, но сам
запрос его будит, а Telegram повторяет доставку несколько минут.
Карточка придёт с задержкой до минуты. На бесплатном плане это ожидаемо.

## Тесты

- Разбор апдейта: сообщение с `/start <код>`, без кода, не текстовое,
  постороннее — каждое даёт ожидаемое решение. Без сети.
- Сборка карточки: содержит время с пометкой UTC и контакт менеджера,
  **не содержит** вердикт модели.
- База: код генерируется уникальным, поиск заявки по коду работает,
  первый `chat_id` привязывается, чужой `chat_id` получает отказ,
  тот же `chat_id` получает карточку повторно.
- Бот без `TELEGRAM_BOT_TOKEN`: воронка доходит до подтверждения,
  ссылка не показывается, ничего не падает.

## Переменные окружения

| Переменная | Обязательна | Смысл |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | нет | Токен от @BotFather. Не задан — фича выключена |
| `TELEGRAM_BOT_USERNAME` | вместе с токеном | Имя бота для ссылки, без `@` |
| `TELEGRAM_WEBHOOK_SECRET` | вместе с токеном | Произвольная случайная строка. Ею подписываются входящие апдейты |

Бота заводит человек у @BotFather. Регистрация адреса вебхука в Telegram
(`setWebhook`) — разовое действие, выполняется человеком после деплоя.

## Границы работы

Не входит: напоминания перед интервью, отмена и перенос из Telegram,
кнопки в карточке, уведомления рекрутеру, вложения и файлы, любые
сообщения кандидату кроме карточки по нажатию Start.
